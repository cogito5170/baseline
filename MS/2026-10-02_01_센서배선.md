## 무엇을 했나

`llmsensor.sense()` 의 출력을 MS 의 텔레메트리 신호로만 편다. **MS 는 Sensor 를 import 하지 않는다** -- 계약은 출력의 데이터 꼴(dict · JSON)이고,
Sensor 는 `pip install ".[sensor]"` 선택 의존이다.

| Sensor 칸 | 성격 | 처리 |
|---|---|---|
| `telemetry` (토큰 · 턴 · 도구 호출 · 실패 · 재시도 · 지연) | 측정 | 받음 → `sensor.tel.*` |
| `readings` (센서 다섯 + 하위: 상태 · 값 · 수 칸) | 관측 | 받음 → `sensor.<센서>[.<하위>].status · .value · .<수 칸>` |
| `residual` | 유도된 측정 | 받음 → `sensor.res.*` |
| `fusion` (Q) | 추정 -- 판독의 함수 | **안 받음**(받으면 같은 증거를 두 번 센다 · 뜻은 MS 모형이 정한다) → 격리함에 이름만 |
| `verdict` (ACCEPT · RETRY … + 정책 제안) | 결정 | **안 받음**(받으면 Sensor 와 Policy 가 섞인다) → 격리함에 이름만 |

**수만 받는다.** 코드로 확인한 바 Sensor 판독의 `why` · `detail` 에 날글이 섞인다: outcome 의 stdout · stderr 마지막 400 자(비밀이 섞일 수 있다) ·
execution 의 파일 경로 · constraint 의 답의 값 · 명령줄. 그래서 상태 · 수 · 참거짓과 **센서별 수 칸 화이트리스트**(목록은 길이만)만 받고,
화이트리스트 밖 칸은 버리고 **이름만** `dropped` 에 적는다. 판독은 OpenTelemetry `gen_ai.evaluation.result` 꼴로도 낸다(설명 칸 없이).

## 확인한 것

- 진짜 Sensor 출력에 비밀을 일부러 심은 픽스처(stdout 의 비밀 표지 3 회 · 파일 경로 1 회)에서, 신호 · 격리함 어디에도 비밀 · why 글이 없다
- fusion · verdict 는 신호가 되지 않고 이름만 남는다 · UNKNOWN 은 UNKNOWN 그대로(값이 없으면 신호도 없다)
- Sensor 가 새 칸을 더하면(글이든 수든) 받지 않고 이름만 남긴다 · 잘못된 타입(글로 된 수 · 모르는 상태 · NaN)은 버린다
- 모형(③)이 없으면 Sensor 신호는 **전부 unbound** 로 격리된다 -- 그래프가 바뀌지 않는다(Telemetry ≠ State)
- 시험이 헛돌지 않는지: 코드를 6 가지로 망가뜨렸다(why 를 신호로 · Q · 판정을 신호로 · 출력 꼬리 받기 · 화이트리스트 밖 통과 · 목록을 통째로 · UNKNOWN 을 OK 로) -- 전부 빨개진다.
  출력 꼬리 받기는 첫 시도가 헛돌았다(변이가 실제로 꼬리를 통과시키지 않았다) -- 진짜 누출로 다시 넣어 빨개지는 것을 확인했다

## 확인하지 못한 것

- **선행조사는 전부 검색 조각만 봤다.** 가장 가까운 것: MAPE-K(Kephart & Chess 2003) -- 이 구조 자체가 MAPE-K 다 / ASPO(arXiv:2605.00741) --
  LLM 제안 + 결정론적 집행을 MAPE-K 안에 둔 것이 우리 아래 절반(⑥~⑦)과 거의 같다. ASPO 전문을 읽으면 우리가 다른 점이 "LLM 쓰임새 자체를 감지 대상으로" 뿐일 수 있다
- 화이트리스트는 Sensor `d4b80b3` 기준이다. Sensor 가 바뀌면 시험(`LiveSensor`)이 알린다 -- 단 llmsensor 가 깔린 곳에서만 돈다
- Sensor 신호의 **뜻**(상태)은 아직 없다 -- ③ 의 일

## baseline 에 묻는 것

1. Q(증거 융합)를 MS 가 받지 않고 판독만 받기로 한 결정 -- MS 모형(③)이 판독을 묶어 뜻을 정한다. 이 경계가 맞나?
2. ③ 에서 만들 센서 상태의 첫 후보: `outcome_confidence`(판독의 띠) · `false_success_risk`(완료 주장 ↔ 마지막 검증 실패) · `loop_risk` · `cost_anomaly`. 더하거나 뺄 것?
