# 지원자 사실 시트 (baseline 이 저장소에서 확인한 것만)

규칙: 아래 "확인된 사실"만 경험으로 쓴다. "모르는 것"은 지어내지 말고 대괄호 자리표시자([이름] 등)로 남긴다.
숫자는 그대로 쓴다(반올림·과장 금지).

## 모르는 것 → 자리표시자
- [이름], [연락처], [이메일], [생년월일]
- [학력], [전공], [학위] (로봇공학 전공 여부·석사 여부 모름)
- [경력 연수], [직장명], [재직 기간]
- [C++ 사용 경험], [Isaac Sim / Isaac Lab 경험], [로봇 하드웨어 경험]
- [패션·디자인 전공 또는 실무 경험], [포트폴리오 이미지·영상 링크], [병역 사항]

## 확인된 사실 (저장소: 어디서 확인했는지 괄호)

1. GA Engine (ga-sdk, 0.17.0): 허브 세션 하나가 지시(directive)와 보고(report) 양식으로 작업 세션 여럿을 굴리는 고리를
   기계로 돌리는 엔진. 핵심은 Python 표준 라이브러리. 새 클론에서 1,347 개 시험이 통과하는 상태로 관리.
   - ga judge: 보고를 믿지 않고 새 클론에서 다시 시험하고, 일부러 코드를 망가뜨리는 변이(mutation)로 시험이 진짜 잡는지 확인.
   - ga hub: 판정을 6 KB 이하 판정 카드 + 작은 모델 1 턴(받음 / 되돌림 / 사람에게 묻기)으로 줄임.
   - ga act: 작은 모델이 EDIT · NEW · RUN 같은 정해진 행동 양식으로만 코드를 고치는 실행 고리.
   - 모델 라우터: 항목마다 시작 모델과 턴 수를 한 번만 정함 — 항목에 적힌 경로 → 결과 장부(같은 유형 3 건 성공) →
     파일 내용 없이 2 KB 이하 카드로 강한 모델 1 턴 판단; 막히면 한 칸만 위 모델로; 가장 싼 칸은 3 턴 안에 포기.
2. 토큰 실측 (baseline BD-416 · BD-458):
   - agy 기본 에이전트의 턴당 고정 입력 9,852 토큰 → 도구 없는 에이전트로 2,530–2,958 토큰.
   - 작은 시험 과제에서 모델이 10 턴 동안 37,023 토큰을 쓰고 실패한 것을 보고, 진전 없는 턴을 세는 규칙을 고쳐 3 턴에 멈추게 함.
   - 리포트 화면 한 장을 작은 모델(gpt-oss-120b-medium)이 1 턴, 약 4,7xx 토큰으로 구현(Token, AGA5 · AGA6).
3. GA Console: 로컬 웹 콘솔. 다크 · 흑백 · 미니멀. 디자인 원칙: "장식·표시용 정적인 선은 없애고, 기능을 나타내는 선과
   실시간으로 움직이는 레이아웃은 남긴다". 묻기 화면(Enter 로 보내기, 토큰 사용량 표시). VM 에서 24 시간 돌고,
   다른 PC 에서는 SSH 터널로만 연다.
4. Token (ga Console 제품): AI 사용 기록을 받아 토큰 · 비용 · 품질을 시각화하고 견적 · 절약 조언 · 개인화를 하는 서비스.
5. llmsensor (Sensor): LLM 을 하나의 자율 시스템으로 보고 센서를 다는 연구. 센서 다섯이 판독값(OK · SUSPECT · FAULT ·
   UNKNOWN)을 내고, 잠재 상태 P(success | 증거)를 추정하며, 받을지는 LLM 이 아니라 결정론적 판정기가 정한다.
   NASA 식 analytical redundancy(Chow & Willsky 1984)의 "잔차 생성 → 결정" 두 단계를 빌림.
6. 계층 구조 (Telemetry · Sensor · DC · MS): L0 Telemetry "무슨 일이 일어났나"(판단 없이 관측 기록) → L1 Sensor
   "그 관측이 무엇을 뜻하나" → L2 State → L3 DC(Decision Context: 이번 결정에 필요한 상태를 골라 신선도 · 근거 · 제약을
   붙인 고정 스냅숏) → MS(LLM Policy Runtime: 무엇을 보일지 · 어떻게 말할지 · 누구에게 물을지 · 제안을 받을지).
   관측 → 상태 추정 → 결정 → 행동의 제어 고리를 LLM 시스템에 적용한 것. 표준 라이브러리만.
7. 여러 모델 운영: Oracle 클라우드 VM(x86_64, 2 코어)에서 Antigravity CLI(agy)로 18 개 모델(Gemini 3.x Flash · Pro,
   Claude Sonnet · Opus 5.5, GPT-OSS 120B)을 항목마다 골라 씀. 세션 사이 통신은 git 우편함. 30 분마다 스스로 갱신.
8. 최근 6 개월 안에 직접 쓴 AI 기술(포트폴리오 질문용 후보): 여러 모델을 한 고리로 묶는 에이전트형 코딩
   (Antigravity CLI 의 도구 없는 에이전트 · 모델 라우팅). 가능성: 작은 모델이 정해진 양식 안에서는 1 턴에 화면 하나를 만든다.
   한계: 기본 설정의 고정 비용(턴당 약 1 만 토큰), 정확한 문자열 편집에 약함, 진전 없는 반복.
