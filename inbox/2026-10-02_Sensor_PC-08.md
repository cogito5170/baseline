## 3. 결정이 필요한 것

**Q1. 런타임 압축 행동이 DC 어휘에 없다.** Sensor 판 `COMPACT_CONTEXT`(Claude Code 자동 압축을 시키는 것)를 시험 정책에서 `COMPRESS` 로 옮겼지만
같은 행동이 아니다. 런타임에게 압축을 시키는 것과 MS 가 덜 싣는 것은 다른 행동이다. 이 데이터에서는 결정이 한 번도 안 바뀌어 수에는 영향이 없다.
- (a) `context_policy` 에 `COMPACT(runtime_compaction)` 를 되돌린다 — MS 에는 실행기가 없다
- (b) **권고:** 에이전트 런타임 자신의 맥락을 다루는 목적을 따로 둔다(`agent_context`: `agent.context_pressure` · KEEP · COMPACT). 결정의 주체가 다르다(MS 의 LLM 맥락 vs 런타임의 맥락)
- (c) 버린다

**Q2. Sensor 의 통합 머리.** `nifty-volta`(a99be64)에 `nice-wright` · `jolly-einstein` · 내보내기 계약 · PC-08 이 다 있다. 이것을 Sensor 의 기준 갈래로 삼아도 되나?
다른 Sensor 세션이 `nice-wright` · `jolly-einstein` 에 계속 얹으면 다시 갈라진다.

**Q3. DC X-2.** DC `nifty-volta`(d9f5fe4)는 PC-01 · PC-05(DC 쪽) · Sensor 계약 · PC-08 · PC-14 를 담는다. §13.3 권고대로 DC `jolly-einstein` 을 버리는 것을 확정해 주면 그렇게 표기한다.

**Q4. 신선한 집계가 낡은 구성 요소 위에 선다.** 실제 세션 기록에서 `agent.execution_health = UNRESOLVED_FAILURES` 는 FRESH 인데, 그 원인인
`tool[WebFetch].tool_execution_health` 는 7 시간 전 것이라 STALE 이었다. 집계 상태는 새 관측마다 다시 계산되어 늘 FRESH 가 된다.
- (a) **권고 (Sensor 쪽):** 집계 상태의 `observed_at` 을 '그 값을 정한 근거' 의 시각으로 — UNRESOLVED 면 미해결 겨냥 중 가장 늦은 결과 시각. 규칙 판본을 올린다
- (b) DC 가 상태끼리 맞대어 본다(GAP-11) — 어떤 쌍이 같은 것을 가리키는지 근거가 없다
- (c) 그대로 두고 문서화
