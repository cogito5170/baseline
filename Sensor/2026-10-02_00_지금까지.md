## 3. 이 폴더를 열기 직전에 한 것 -- S1 `liveness_state` (`24265da` 설계 · `28c8af4` 구현)

센서 계층만 바꿨다. 텔레메트리 수집기 · 꼴은 손대지 않았다.

**입력 계약**: `run` 레코드의 칸 다섯이다.

- `terminal_seen` · `transport_closed` · `turn_open` · `activity_at_ms` · `heartbeat_at_ms`
- `turn_open` 은 "입력을 **받은 순간부터** 차례가 끝날 때까지 true" 다.

| 값 | 조건 | 근거 종류 |
|---|---|---|
| ENDED | 종료 사건, 또는 런타임 종료 선언(기존 `termination` 재사용 -- 전부 null 인 요약은 제외) | OBSERVED / RUNTIME_DECLARED |
| ENDED_WITHOUT_TERMINAL | 흐름이 닫혔는데 종료 사건이 없다 | DEFINITIONAL |
| AWAITING_INPUT | 차례가 닫혀 있다 | OBSERVED |
| IN_TURN | 차례가 열려 있고 운영자 무음 문턱이 없다 | OBSERVED |
| ACTIVE / STALLED | 차례가 열려 있고 `liveness_timeout_ms`(운영자, 기본 없음) 대비 무음 | OPERATOR_ASSUMED |

- **내지 않는 값.** DEAD 는 기록 안에서 판정할 수 없다. ALIVE 는 문턱 없는 ACTIVE 가 된다.
- **엔진에 더한 것.** 다른 상태의 뜻은 그대로다(회귀 확인, §1).
  - `Result.basis` -- 값마다 근거 종류를 따로 남긴다.
  - `Rule.clock_values` -- ACTIVE · STALLED 는 평가 순간에만 참이다. 뒤 시각으로 질의하면 STALE.
  - `StateEngine.advance(run_id, now)` -- 시각 규칙만 다시 잰다. 시계는 읽지 않고, 거꾸로 가는 now 는 거절한다.
- **첫 구현의 결함 하나를 시험이 잡았다.** 종료 칸이 전부 null 로 보고된 요약을 ENDED 로 읽었다. 고쳤다.
- 상태 수 상한 시험을 12 에서 13 으로 올렸다. 설계상 유일한 새 상태다.

## 6. baseline 에 묻는 것

1. **`liveness_state` 의 자리.** BD-35 · BD-22 로 보면 건강 성격 상태라 ASSESS(Health 저장소) 소유다.
   - 어느 쪽으로 할까: (a) Sensor 에 두고 소유 층 표시만 ASSESS 로 (b) Health 저장소로 옮긴다.
   - DATA_FLOW C1 의 `collector.liveness` 는 **수집기**의 liveness 이고, S1 은 **실행(task)** 의 liveness 다. 대상이 다르다.
   - 값 이름도 하나로 맞출까. C1 은 `ENDED_WITHOUT_RESULT`, S1 은 `ENDED_WITHOUT_TERMINAL` 이다.
2. **S1 입력 칸 이름.** BD-28 에 따라 Telemetry 저장소의 이름을 Sensor 가 따를까, Sensor 가 낸 다섯 칸을 Telemetry 저장소에 제안할까.
3. **수집기 결함 D1–D4 와 런타임 행동 수집의 주인 -- 기준선과 사용자 지시가 부딪힌다.**
   - PC-20 은 D1–D4 를 "Sensor 세션 소관" 으로 적었다.
   - DATA_FLOW §7 은 런타임 행동(압축 등)을 "Sensor 수집기가 Observation 으로" 거둔다고 적었다.
   - 그런데 사용자는 그 뒤에 "텔레메트리는 센서 계층과 분리해 따로 만든다, Sensor 는 센서만 설계하라" 고 지시했다(2026-10-02).
   - 그래서 Sensor `telemetry/collect.py` 는 손대지 않았다. 결함은 **계약 조건**으로만 적어 두었다(`SENSOR_HEALTH_DESIGN.md` §1.2).
   - PC-20 을 Telemetry 저장소의 일로 옮길까, Sensor 가 할까.
4. **§5 의 순서와 S3 의 새 상태 승인.**
5. **PC-08(Sensor DC 걷어 내기)을 언제 할까.** 함께 빠지는 것이 있다.
   - PC-08 이 짚은 파일들: `decision/context` · 엔진 `decision_context()` · `policy/*` · `eval/ms_end_to_end.py` · `tests/test_decision_context.py` · `tests/test_decision.py`
