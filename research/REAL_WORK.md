## 4. 실험 설계 (후속 연구 RW1)

- **대상:** Token MVP(로드맵 작업 항목, 역할 6개: design · frontend · core-backend · ingestion-analytics · consulting · infra).
- **비교:** (가) 지금의 허브 방식(지시 하나 = 세션 하나, 사람 대신 baseline 이 판정) 대 (나) F1–F6 를 갖춘 ga 노드 풀. 같은 작업 항목 묶음, 같은 판정.
- **잴 것:** 판정 통과 작업당 토큰(API 정가 환산 · CLI 비용 두 기준), 첫 시도 판정 통과율, 재작업 횟수, 병합 충돌 수, 사람 개입 횟수, 완료까지 걸린 시간, 문맥 크기 분포(대량 주입 호출 비율).
- **작은 과제 결과와의 대조:** FINAL_TASK 배율(대량 주입 25–63배, 구조 C 의 맞힌 작업당 토큰 53–59% 절감)이 실제 작업에서 유지되는지.
- **한계를 미리 적음:** 작업마다 크기가 달라 분산이 크다. 작업 크기(바뀐 줄 · 파일 수)로 정규화해 함께 보고한다.
