**`throwError(inputId, lineNum, msg)` (14–19줄).**
- `new Error(msg)`에 속성 두 개를 붙여 던진다. JS의 `Error`는 보통 객체라 아무 속성이나 더할 수 있다. 화면은 `err.inputId`로 "어느 칸"을, `err.lineNum`으로
  "몇째 줄"을 안다.
- `inputId` 값(`'visitLines'`, `'transportLines'`, `'lodgingLines'`)은 텍스트 상자의 `id`와 **같은 글자**다. 화면은 `inputId + 'Error'`로 `<span>`의
  `id`를 만든다(index.html 169줄) — 이름 규칙이 곧 연결이다.
- 메시지에서 줄 번호가 빠졌다(`… on line ${item.lineNum}` → `lineNum` 속성). 줄 번호는 화면이 `(Line N: …)`로 붙인다. 그래서 메시지만 보는 곳
  (예: 콘솔)에서는 줄 번호가 보이지 않는다.
- `Too many visit cities`는 특정 줄이 아니라 `lineNum = null`(29줄) → 화면에 `Line ?`.
- 함수 이름은 "던진다"지만 `throw`가 함수 **안**에 있다. 그래서 `if (…) throwError(…)` 뒤의 코드는 실행되지 않는다(함수가 돌아오지 않으므로).

이 세션에서 `c4c96ec`의 `parseData`로 확인한 값(4장의 실험 스크립트 끝 네 줄):

```text
inputId=visitLines lineNum=1 message=Visit city format error
inputId=transportLines lineNum=3 message=Unknown city 'Z'
inputId=visitLines lineNum=null message=Too many visit cities (max 10).
no throw, V = 0
```

빈 줄 두 개 뒤의 모르는 도시가 `lineNum=3`이다(빈 줄을 세는 규칙, code/03 3.1절). 방문 도시가 0개인 입력은 파서가 통과시키고 엔진이 막는다(code/05 error_test 시험 1).

**`encodeState` / `decodeState` (337–347줄).**
- `JSON.stringify(state)` → `encodeURIComponent(…)` → `btoa(…)`. `btoa`는 한 글자가 1바이트(Latin-1)인 문자열만 받는다. 한글 도시 이름이 있으면
  `btoa`가 바로 실패하므로, 먼저 `encodeURIComponent`로 `%EC%84%9C…` 같은 ASCII로 바꾼다. 되돌릴 때는 정확히 반대 순서(`atob` → `decodeURIComponent` → `JSON.parse`).
- `decodeState`는 앞의 `#`을 떼고, 무엇이든 실패하면 `null`(잘못된 해시로 페이지가 죽지 않게). 길이 2 미만이면 바로 `null`.
- 이 세션에서 확인(4장의 실험 스크립트 앞 일곱 줄):

```text
example hash length: 33764 roundtrip equal: true
plain btoa(JSON) with Korean: InvalidCharacterError - Invalid character
encodeState Korean roundtrip: true
decodeState("#!!bad"): null
decodeState("#"): null
chars + / = in example hash: true
NaN after roundtrip: {"days":null}
```

읽는 법: 예시 데이터 전체(이동 448줄, 숙박 56줄)를 담으면 해시가 33,764자다(연습 문제 3). base64 글자에는 `+`, `/`, `=`가 섞이지만 해시 안에서는
그대로 쓸 수 있다. `NaN`은 JSON에 없으므로 `null`로 바뀐다 — 칸을 비운 채 공유하면 받는 쪽에서 그 칸이 다르게 보일 수 있다.
