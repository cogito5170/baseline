# 03 · VM-18 첫 프론트엔드: Web Worker + 최소 화면 + V6 (analy_agent `79099ec`, 브랜치 `vm/trip-wk2`)

커밋 흐름: `b3d8932`(VM-17, code/02에서 다룸) → `716d3ac`(VM-18 rev 1, 불합격) → `79099ec`(VM-18 rev 2, 채택).

## 1. 무엇·왜

**무엇.** 엔진을 브라우저에서 처음으로 쓰는 화면이다. 빌드 단계도 npm 의존성도 없는 순수 JS 모듈 세 개(SPEC 4.2 ADR-5의 (a))와
시험 세 개, 그리고 CI web 작업의 단계 추가로 이루어진다.

```text
index.html (화면, <script type="module">)
  │  ① parseData(...)        ← model.mjs (순수 JS: CSV → 평탄 배열)
  │  ② worker.postMessage({type:'optimize', payload: parsed})
  ▼
worker.mjs (module Web Worker)
  │  ③ callEngine(mod, payload)   ← model.mjs (malloc → HEAP 복사 → _trip_optimize → decodePlans → free)
  │       └─ engine.mjs + engine.wasm (VM-17의 WASM 빌드)
  │  ④ self.postMessage({type:'success', numPlans, plans}) 또는 {type:'error', error}
  ▼
index.html ⑤ 계획 목록을 그린다
```

SPEC 4장 그림과 같은 모양이다. 핵심은 **model 모듈이 순수 JS**라는 점이다. `parseData`, `decodePlans`, `getExampleData`는 WASM 없이
Node에서 바로 시험할 수 있고(V6), 엔진을 부르는 `callEngine`도 model 모듈에 있지만 엔진 객체를 **인자로 받기** 때문에 model 모듈은
`engine.mjs`를 import하지 않는다. `engine.mjs`를 import하는 곳은 `worker.mjs`와 `tests/wasm.test.mjs` 둘뿐이다.

**왜 Web Worker인가.** SPEC 4.2 ADR-3: 계산 중 화면이 멈추지 않게. 엔진 호출은 동기 함수라서 화면 스레드에서 부르면 계산이 끝날 때까지
클릭도 그리기도 멈춘다. 워커에서 부르면 화면 스레드는 메시지만 기다린다.

### 2.2 `trip_optimizer/web/model.mjs` (317줄)

```js
export function parseData({
    startCity,
    endCity,
    visitLines,
    transportLines,
    lodgingLines,
    startDate, // YYYY-MM-DD
    days,
    k,
    costPerMinute
}) {
    // 1. Visit Cities (방문 도시)
    // Format: city,min_stay,max_stay
    const visits = [];
    const cities = new Map();
    cities.set(startCity, 0); // 0 = start
    
    // To handle line numbers properly, we will split and map
    const splitLines = (text) => text.split(/\r?\n/).map((line, i) => ({ text: line.trim(), lineNum: i + 1 })).filter(l => l.text.length > 0);
    
    const visitItems = splitLines(visitLines);
    if (visitItems.length > 10) {
        throw new Error("Too many visit cities (max 10).");
    }
    
    for (const item of visitItems) {
        const parts = item.text.split(',');
        if (parts.length < 3) throw new Error(`Visit city format error on line ${item.lineNum}`);
        const name = parts[0].trim();
        const min = parseInt(parts[1], 10);
        const max = parseInt(parts[2], 10);
        if (cities.has(name)) throw new Error(`Duplicate city ${name} on line ${item.lineNum}`);
        visits.push({ name, min, max });
        cities.set(name, visits.length); // 1..V
    }
    
    const V = visits.length;
    if (!cities.has(endCity)) {
        cities.set(endCity, V + 1); // V+1 = end
    }
    
    const N = V + 2;
    const startMs = new Date(startDate).getTime();
    
    function getDayIndex(dateStr) {
        const d = new Date(dateStr);
        if (isNaN(d.getTime())) return -1;
        const diffMs = d.getTime() - startMs;
        const diffDays = Math.round(diffMs / (1000 * 60 * 60 * 24));
        return diffDays;
    }
    
    const modes = new Map();
    let modesCount = 0;
    
    let skippedTransport = 0;
    const transItems = splitLines(transportLines);
    const transData = [];
    
    for (const item of transItems) {
        // 출발도시,도착도시,날짜(YYYY-MM-DD),수단,가격(원),소요분
        const parts = item.text.split(',');
        if (parts.length < 6) throw new Error(`Transport format error on line ${item.lineNum}`);
        const [from, to, dateStr, mode, priceStr, minsStr] = parts.map(p => p.trim());
        
        let fromIdx = -1, toIdx = -1;
        
        if (from === startCity) fromIdx = 0;
        else if (cities.has(from)) fromIdx = cities.get(from);
        
        if (to === endCity) toIdx = V + 1;
        else if (cities.has(to) && to !== startCity) toIdx = cities.get(to); // to cannot be start city node 0
        
        if (fromIdx === -1 && from !== startCity && !cities.has(from)) throw new Error(`Unknown city '${from}' on transport line ${item.lineNum}`);
        if (toIdx === -1 && to !== endCity && !cities.has(to)) throw new Error(`Unknown city '${to}' on transport line ${item.lineNum}`);
        
        const dayIdx = getDayIndex(dateStr);
        if (dayIdx < 0 || dayIdx >= days) {
            skippedTransport++;
            continue;
        }
        
        if (!modes.has(mode)) {
            modes.set(mode, modesCount++);
        }
        const mIdx = modes.get(mode);
        const price = parseInt(priceStr, 10);
        const mins = parseInt(minsStr, 10);
        
        if (fromIdx !== -1 && toIdx !== -1) {
            transData.push({ from: fromIdx, to: toIdx, day: dayIdx, mode: mIdx, price, mins });
        }
    }
    
    const M = Math.max(1, modesCount);
    
    // Flat arrays initialization
    const legsCount = N * N * days * M;
    const priceArr = new Float64Array(legsCount);
    priceArr.fill(-1); // negative means option doesn't exist
    const minsArr = new Float64Array(legsCount);
    minsArr.fill(0);
    
    for (const t of transData) {
        // ((a × N + b) × D + day) × M + mode
        const idx = ((t.from * N + t.to) * days + t.day) * M + t.mode;
        priceArr[idx] = t.price;
        minsArr[idx] = t.mins;
    }
    
    let skippedLodging = 0;
    const lodgingItems = lodgingLines ? splitLines(lodgingLines) : [];
    
    const lodgingArr = new Float64Array(N * days);
    lodgingArr.fill(0); // 0 by default
    
    for (const item of lodgingItems) {
        // 도시,날짜,1박가격(원)
        const parts = item.text.split(',');
        if (parts.length < 3) throw new Error(`Lodging format error on line ${item.lineNum}`);
        const [city, dateStr, priceStr] = parts.map(p => p.trim());
        
        let cIdx = -1;
        if (city === startCity) cIdx = 0;
        else if (city === endCity) cIdx = V + 1;
        else if (cities.has(city)) cIdx = cities.get(city);
        
        if (cIdx === -1) throw new Error(`Unknown city '${city}' on lodging line ${item.lineNum}`);
        
        const dayIdx = getDayIndex(dateStr);
        if (dayIdx < 0 || dayIdx >= days) {
            skippedLodging++;
            continue;
        }
        
        const price = parseInt(priceStr, 10);
        lodgingArr[cIdx * days + dayIdx] = price;
    }
    
    const stayMinArr = new Int32Array(N);
    const stayMaxArr = new Int32Array(N);
    stayMinArr.fill(0);
    stayMaxArr.fill(0);
    
    for (let i = 0; i < V; i++) {
        stayMinArr[i + 1] = visits[i].min;
        stayMaxArr[i + 1] = visits[i].max;
    }
    
    const nodeToCity = new Array(N);
    nodeToCity[0] = startCity;
    nodeToCity[V + 1] = endCity;
    for (let i = 0; i < V; i++) nodeToCity[i + 1] = visits[i].name;
    
    const modeIdxToName = new Array(M);
    for (const [name, idx] of modes.entries()) {
        modeIdxToName[idx] = name;
    }
    if (M === 1 && modesCount === 0) modeIdxToName[0] = "Default";
    
    return {
        V, days, M,
        priceArr, minsArr, lodgingArr, stayMinArr, stayMaxArr,
        departMin: 0, departMax: days - 1,
        costPerMinute, k,
        skippedLines: skippedTransport + skippedLodging,
        nodeToCity,
        modeIdxToName,
        startDate
    };
}

export function decodePlans(outArray, numPlans, k, V, nodeToCity, modeIdxToName, startDateStr) {
    const plans = [];
    let ptr = 0;
    
    const startMs = new Date(startDateStr).getTime();
    function formatDay(dayIdx) {
        const d = new Date(startMs + dayIdx * 24 * 60 * 60 * 1000);
        return d.toISOString().split('T')[0];
    }
    
    for (let i = 0; i < numPlans; i++) {
        if (ptr >= outArray.length) break;
        
        const objective = outArray[ptr++];
        const transport_price = outArray[ptr++];
        const lodging_price = outArray[ptr++];
        const travel_minutes = outArray[ptr++];
        const numLegs = outArray[ptr++];
        
        const legs = [];
        for (let l = 0; l < numLegs; l++) {
            const from = outArray[ptr++];
            const to = outArray[ptr++];
            const day = outArray[ptr++];
            const mode = outArray[ptr++];
            const price = outArray[ptr++];
            const minutes = outArray[ptr++];
            legs.push({
                from: nodeToCity[from],
                to: nodeToCity[to],
                date: formatDay(day),
                mode: modeIdxToName[mode],
                price,
                minutes
            });
        }
        
        const numStays = outArray[ptr++];
        const stays = [];
        for (let s = 0; s < numStays; s++) {
            const city = outArray[ptr++];
            const arrive_day = outArray[ptr++];
            const nights = outArray[ptr++];
            const lodging = outArray[ptr++];
            stays.push({
                city: nodeToCity[city],
                arriveDate: formatDay(arrive_day),
                nights,
                price: lodging
            });
        }
        
        plans.push({
            objective,
            transport_price,
            lodging_price,
            travel_minutes,
            legs,
            stays
        });
    }
    
    return plans;
}
export function getExampleData() {
    const startCity = 'Seoul';
    const endCity = 'Seoul';
    const startDate = '2027-04-01';
    const days = 14;
    const visitLines = "Tokyo,2,3\nOsaka,1,2\nKyoto,2,3\nFukuoka,1,2";
    
    const cities = ['Seoul', 'Tokyo', 'Osaka', 'Kyoto', 'Fukuoka'];
    let transportLines = "";
    let lodgingLines = "";
    
    for (let d = 0; d < 14; d++) {
        const dateStr = `2027-04-${(d+1).toString().padStart(2, '0')}`;
        for (const c of cities) {
            if (c !== 'Seoul') lodgingLines += `${c},${dateStr},${50000 + (c.length * 10000)}\n`;
        }
        for (let i = 0; i < cities.length; i++) {
            for (let j = 0; j < cities.length; j++) {
                if (i === j) continue;
                const c1 = cities[i];
                const c2 = cities[j];
                if (c1 === 'Seoul' || c2 === 'Seoul') {
                    transportLines += `${c1},${c2},${dateStr},Flight,${200000 + (d * 5000)},120\n`;
                } else {
                    transportLines += `${c1},${c2},${dateStr},Train,${10000 + (d * 1000)},60\n`;
                    transportLines += `${c1},${c2},${dateStr},Bus,${5000},180\n`;
                }
            }
        }
    }
    
    return {
        startCity, endCity, startDate, days, visitLines, transportLines, lodgingLines
    };
}

export function callEngine(mod, parsed) {
    const p = parsed;
    
    const ptrPrice = mod._malloc(p.priceArr.length * 8);
    const ptrMinutes = mod._malloc(p.minsArr.length * 8);
    const ptrLodging = mod._malloc(p.lodgingArr.length * 8);
    const ptrStayMin = mod._malloc(p.stayMinArr.length * 4);
    const ptrStayMax = mod._malloc(p.stayMaxArr.length * 4);
    
    const out_len = mod._trip_output_size(p.V, p.k);
    if (out_len <= 0) {
        mod._free(ptrPrice); mod._free(ptrMinutes); mod._free(ptrLodging); mod._free(ptrStayMin); mod._free(ptrStayMax);
        throw new Error("Invalid output size");
    }
    const ptrOut = mod._malloc(out_len * 8);
    
    mod.HEAPF64.set(p.priceArr, ptrPrice / 8);
    mod.HEAPF64.set(p.minsArr, ptrMinutes / 8);
    mod.HEAPF64.set(p.lodgingArr, ptrLodging / 8);
    mod.HEAP32.set(p.stayMinArr, ptrStayMin / 4);
    mod.HEAP32.set(p.stayMaxArr, ptrStayMax / 4);
    mod.HEAPF64.fill(0.0, ptrOut / 8, ptrOut / 8 + out_len);
    
    const numPlans = mod._trip_optimize(
        p.V, p.days, p.M,
        ptrPrice, ptrMinutes, ptrLodging,
        ptrStayMin, ptrStayMax,
        p.departMin, p.departMax, p.costPerMinute,
        p.k, ptrOut, out_len
    );
    
    if (numPlans < 0) {
        const errPtr = mod._trip_last_error();
        const errStr = mod.UTF8ToString(errPtr);
        mod._free(ptrPrice); mod._free(ptrMinutes); mod._free(ptrLodging); mod._free(ptrStayMin); mod._free(ptrStayMax); mod._free(ptrOut);
        throw new Error(errStr);
    }
    
    const outActual = new Float64Array(mod.HEAPF64.subarray(ptrOut / 8, ptrOut / 8 + out_len));
    const plans = decodePlans(outActual, numPlans, p.k, p.V, p.nodeToCity, p.modeIdxToName, p.startDate);
    
    mod._free(ptrPrice); mod._free(ptrMinutes); mod._free(ptrLodging); mod._free(ptrStayMin); mod._free(ptrStayMax); mod._free(ptrOut);
    
    return plans;
}
```

```js
        if (!modPromise) {
            modPromise = Module();
        }

            self.postMessage({ type: 'error', error: err.message || String(err) });

    }
};
```

## 3. 해설

### 3.1 `model.mjs` — `parseData` (1–171줄): CSV → 엔진 배열

입력은 화면의 텍스트 상자 문자열 그대로다. 출력은 엔진 C 인터페이스(SPEC 4.1)에 그대로 넘길 수 있는 평탄 배열과, 결과를 사람 말로
되돌리는 데 필요한 표(`nodeToCity`, `modeIdxToName`, `startDate`)다.

**줄 나누기와 줄 번호 (19줄).** `splitLines`는 `split(/\r?\n/)` → 각 줄에 `lineNum: i + 1`을 **먼저** 붙이고 → 빈 줄을 **나중에** 거른다.
그래서 오류 메시지의 줄 번호는 텍스트 상자에서 눈에 보이는 줄 번호(빈 줄 포함)와 같다. 이 세션에서 확인:
`transportLines: '\n\nA,Z,2027-04-01,T,1,1'` → `Unknown city 'Z' on transport line 3`. 윈도 줄바꿈(`\r\n`)도 같은 규칙으로 처리된다.

**노드 번호 (14–42줄).** SPEC 3.1의 노드 규칙 그대로: 0 = 출발 도시, 1..V = 방문 도시(입력 순서), V+1 = 귀국 도시, N = V + 2.
- 22–24줄: 방문 도시가 10개를 넘으면 오류(엔진 한도. SPEC F1의 화면 한도 8은 아직 검사하지 않는다).
- 28줄: 필드가 3개 미만이면 `Visit city format error on line N`. 32줄: 같은 이름이 두 번이면 `Duplicate city`.
- 30–31줄 `parseInt`: 숫자가 아니면 `NaN`이고, 이 값은 140–148줄에서 `Int32Array`에 들어가며 0이 된다. 즉 방문 도시의 박수 칸에 글자를
  넣어도 파서는 오류를 내지 않는다.
- 38–40줄: 귀국 도시가 맵에 없을 때만 V+1로 등록한다. 출발 = 귀국(예시: 서울 → 서울)이면 맵에는 0으로만 있고, 노드 V+1은 71줄과 152줄에서
  이름으로 따로 다룬다(SPEC 3.1 "같은 도시여도 엔진에서는 별개 노드").

**날짜 → 인덱스 (43–51줄).** `new Date('YYYY-MM-DD')`는 UTC 자정으로 해석되므로 두 날짜의 밀리초 차를 하루로 나눠 `Math.round`하면
0, 1, 2, …가 된다. 날짜 문자열이 잘못되면 −1(47줄)이라 바로 아래 "기간 밖"으로 빠진다.
- 확인한 구멍: **시작일 자체**가 비어 있으면 `startMs`가 `NaN`이고 모든 줄의 `dayIdx`가 `NaN`이 된다. `NaN < 0 || NaN >= days`는 거짓이라
  건너뛴 줄로 세지 않고, `priceArr[NaN] = …`은 형식 배열에서 무시된다. 이 세션에서 `startDate: ''`로 돌린 결과: 건너뜀 0, 쓰인 가격 0개,
  숙박 0개 — 오류 없이 "구간이 하나도 없는 문제"가 된다.

**이동 CSV (53–93줄) — SPEC 4.3의 세 규칙이 여기 있다.**
1. *알 수 없는 도시는 줄 번호와 함께 오류* — 74–75줄. 이 검사가 77–81줄의 기간 검사보다 **앞**에 있어서, 기간 밖 날짜인 줄이라도 도시
   이름이 틀리면 오류다(확인: `A,Z,2030-01-01,...` → `Unknown city 'Z' on transport line 1`).
2. *기간 밖 날짜 줄은 건너뛰고 센다* — 77–81줄. 조건은 `dayIdx < 0 || dayIdx >= days`, 즉 허용 범위는 day 0..D−1.
   (확인: days = 5에서 `2027-04-05`(day 4)는 들어가고 `2027-04-06`(day 5)은 건너뜀 1.)
3. *수단은 등장 순서대로 번호* — 83–85줄. 번호를 매기는 위치가 기간 검사 **뒤**라서, 정확히는 "기간 안 줄들 중 등장 순서"다. 기간 밖
   줄에만 나온 수단은 번호를 받지 않는다(확인: `Ship`(기간 밖) → `Bus` → `Ship` 순서의 입력에서 `M = 2`, 수단표 `['Bus', 'Ship']`).

그 밖에 코드가 실제로 하는 일:
- 63줄: 필드 6개 미만이면 `Transport format error on line N`. 64줄에서 각 필드를 `trim()`.
- 71–72줄: 도착지가 출발 도시(노드 0)인 구간은 받지 않는다. 출발 ≠ 귀국일 때 `B,A,...`(A = 출발 도시)는 74–75줄의 오류도 아니고
  건너뜀 개수에도 들어가지 않고, 90줄 조건에서 **조용히 버려진다**(확인: 쓰인 가격 0개, `skippedLines` 0). 수단 번호는 이미 받은 뒤다.
- 87–88줄 `parseInt`: `"10.5"`는 10, `"abc"`는 `NaN`. `NaN`은 그대로 `priceArr`에 들어간다(확인). 엔진이 `price and minutes must be whole
  numbers`(c_api.cpp 49줄)로 −1을 돌려줄 입력이다.
- 104–109줄: 같은 (출발, 도착, 날, 수단) 줄이 두 번 오면 **뒤의 값이 남는다**(확인: 100 다음 50 → 50). 더 싼 값을 고르지 않는다.

**평탄 배열 배치 (95–109줄).** `M = max(1, 수단 수)`(95줄). 구간 배열 길이는 `N × N × D × M`(98줄), 가격은 −1(= 선택지 없음, SPEC 3.1),
분은 0으로 채운 뒤 106줄의 공식으로 채운다.

```text
idx = ((a × N + b) × D + day) × M + mode        (SPEC 4.1, model.mjs 106줄)
```

가장 바깥이 출발 노드 a, 가장 안쪽이 수단이다. 같은 (a, b, day)의 수단들이 메모리에서 붙어 있다. 예시 데이터: N = 6, D = 14, M = 3 →
길이 6 × 6 × 14 × 3 = 1512, 그중 448칸이 채워진다(이 세션에서 계산). 숙박은 `lodging[c × D + day]`(137줄), 기본값 0(115줄).
- SPEC 4.3은 "숙박 CSV가 없으면 0으로 계산하고 화면에 '숙박비 미포함'이라고 표시"라고 한다. 0으로 계산하는 부분만 있고, 숙박 CSV가
  비었는지 알려 주는 값은 반환 객체에 없다(반환 키: `V, days, M, priceArr, minsArr, lodgingArr, stayMinArr, stayMaxArr, departMin, departMax,
  costPerMinute, k, skippedLines, nodeToCity, modeIdxToName, startDate`).

**체류 범위·이름표 (140–170줄).** `stay_min/max`는 `Int32Array(N)`, 노드 0과 V+1은 0. 출발 가능 기간은 `0..days−1` 고정(164줄; SPEC F1의
"출발 가능 기간" 입력은 아직 없음). 159줄: 기간 안 이동 줄이 하나도 없으면 수단 이름표가 `"Default"` 하나.
`skippedLines`(166줄)는 이동 + 숙박의 건너뜀 합이다.

### 3.2 `model.mjs` — `decodePlans` (173–236줄): 출력 배열 → 계획 객체

엔진 출력 배치(SPEC 4.1, c_api.cpp 82–96줄)를 그대로 거꾸로 읽는다. 포인터 `ptr` 하나가 앞으로만 간다.

```text
계획마다:  목적값, 교통비, 숙박비, 이동분, 구간수L,  L × (출발, 도착, 날짜, 수단, 가격, 분),  체류수S,  S × (도시, 도착일, 박수, 숙박비)
           186–190줄                              193–208줄                               210줄      212–223줄
```

- 노드 번호 → 도시 이름은 `nodeToCity`, 수단 번호 → 이름은 `modeIdxToName`, 날 인덱스 → `YYYY-MM-DD`는 178–181줄(`startMs + day × 하루`를
  `toISOString`의 앞 10자로). UTC로 계산하고 UTC로 출력하므로 브라우저 시간대에 따라 하루 밀리지 않는다.
- 184줄 `if (ptr >= outArray.length) break;`는 계획 수가 배열보다 많다고 잘못 들어온 경우의 방어다.
- 인자 `k`와 `V`는 함수 안에서 쓰이지 않는다(계획 길이는 각 계획의 구간 수·체류 수로 정해지므로 필요 없다).

### 3.3 `model.mjs` — `getExampleData` (237–271줄)

서울 출발·귀국, 방문 도쿄 2–3박·오사카 1–2박·교토 2–3박·후쿠오카 1–2박, 2027-04-01부터 14일. 가격은 지어낸 값이다(화면 29줄의 안내문).
- 숙박: 서울 제외 4도시 × 14일 = 56줄, 1박 `50000 + 도시이름길이 × 10000` → 도쿄·오사카·교토 100,000, 후쿠오카 120,000.
- 이동: 하루에 서울이 낀 쌍 8개 × Flight(`200000 + 5000·d`원, 120분) + 일본 안 쌍 12개 × (Train `10000 + 1000·d`원 60분, Bus 5,000원 180분)
  = 하루 32줄 × 14일 = 448줄. 첫 줄이 `Seoul,Tokyo,…,Flight`이므로 수단 번호는 Flight 0, Train 1, Bus 2.
- 이 함수가 rev 2에서 생긴 이유는 4장 (c). 화면(index.html 60줄)과 V2 시험(wasm.test.mjs 7줄)이 **같은 함수**에서 데이터를 받는다.

### 3.4 `model.mjs` — `callEngine` (273–317줄): 엔진 한 번 부르기

워커와 WASM 시험이 공유하는 유일한 엔진 호출 코드다. 순서:

| 줄 | 하는 일 | 메모 |
|---|---|---|
| 276–280 | 입력 5개 `_malloc`: double 배열은 `길이 × 8`, int 배열은 `길이 × 4` 바이트 | |
| 282 | `out_len = mod._trip_output_size(p.V, p.k)` | 출력 길이 공식을 JS에 다시 쓰지 않고 **엔진에게 묻는다**(c_api.cpp 26–28줄). rev 1은 손 공식(4장 (b)) |
| 283–286 | `out_len <= 0`이면 지금까지 빌린 5개를 돌려주고 throw | k = 0이면 이 길 |
| 287 | 출력 버퍼 `_malloc` | |
| 289–294 | `mod.HEAPF64.set(배열, 포인터 / 8)`, `mod.HEAP32.set(…, 포인터 / 4)`, 출력 칸 0으로 | 매 줄 `mod.HEAPF64`를 새로 읽는다(SPEC 4.1: 메모리가 늘면 뷰가 바뀐다) |
| 296–302 | `_trip_optimize(...)` 14개 인자 | 순서는 C 선언과 같다 |
| 304–309 | 반환값 < 0: `_trip_last_error()` 포인터 → `mod.UTF8ToString` → 6개 해제 → `throw new Error(문자열)` | 아래 "확인한 구멍" |
| 311 | `new Float64Array(mod.HEAPF64.subarray(...))` | `subarray`는 WASM 메모리를 가리키는 창일 뿐이라 해제 전에 `new Float64Array`로 **복사**한다 |
| 312 | `decodePlans(...)` | |
| 314–316 | 6개 해제, 계획 배열 반환 | |

**해제 경로.** 정상(n ≥ 0), 출력 길이 0 이하, 엔진 오류(n < 0) — 코드에 쓰인 세 길은 모두 빌린 것을 돌려준다. 다만 "모든 경로"는 아니다.
`try/finally`가 없어서, 해제 줄에 닿기 **전에** 예외가 나면 그대로 샌다. 그런 지점이 두 군데 있다: 306줄 `mod.UTF8ToString`과 312줄 `decodePlans`.

**확인한 구멍 — 306줄 `mod.UTF8ToString`.** 엔진 링크 옵션(`79099ec`의 `engine/CMakeLists.txt` 18줄)은
`-sEXPORTED_FUNCTIONS=...`만 있고 `-sEXPORTED_RUNTIME_METHODS`가 없다. Emscripten 3.1.64 소스(`tools/link.py`, `src/settings.js`,
`src/modules.mjs`)를 읽어 보면 `EXPORTED_RUNTIME_METHODS`의 기본값은 빈 목록이고, STRICT가 아닐 때 **HEAP 뷰들만** 기본으로 추가된다.
그래서 `mod.HEAPF64`·`mod.HEAP32`는 있지만 `mod.UTF8ToString`은 Module 객체에 붙지 않을 것으로 보인다(-O3 Release 빌드는 ASSERTIONS = 0이라
안내 메시지 없이 `undefined`). 이 판단은 **소스 읽기에 근거한 것이고 실제 WASM으로 실행해 확인하지 않았다**(이 환경에 emcc가 없다).
CI의 두 시험(wasm.test, smoke)은 모두 성공 경로만 지나므로 이 줄은 CI에서도 한 번도 실행되지 않았다.
`UTF8ToString`이 없는 가짜 모듈 객체로 `callEngine`의 JS 흐름만 이 세션에서 돌려 본 결과(가짜 엔진이다 — 진짜 WASM이 아니다):

```text
fake ret=-1 UTF8ToString=true: Error: engine error text | malloc 6, free 6, still allocated 0
fake ret=-1 UTF8ToString=false: TypeError: mod.UTF8ToString is not a function | malloc 6, free 0, still allocated 6
fake ret=0 UTF8ToString=false: plans=0 | malloc 6, free 6, still allocated 0
```

`UTF8ToString`이 있으면 엔진 문장이 그대로 오류가 되고 6개가 모두 해제된다. 없으면 `TypeError`가 나고 307줄의 해제에 닿지 못해 6개가 남는다.
화면에서 이 길에 들어가는 입력은 흔하다. 방문 도시 칸을 비우면 V = 0이고 엔진 첫 검사(`visits must be 1..10…`, c_api.cpp 34–36줄)에서
−1이다. 분당 비용 칸을 비워도 `parseInt('')`가 `NaN`이라 −1(`cost per minute must be a whole number`). 소스 읽기가 맞다면 화면에는
엔진의 오류 문장 대신 `Error during optimization: mod.UTF8ToString is not a function`이 나오고, 입력 버퍼 6개가 워커 메모리에 남는다.
고치는 방법은 연습 문제 2.

### 3.5 `worker.mjs` (23줄): 메시지 규약

1줄 `import Module from './engine.mjs'`는 **정적 ES 모듈 import**다. 그래서 index.html 70줄이 워커를 `{ type: 'module' }`로 만든다.
(고전 워커라면 `importScripts`를 써야 하고, `EXPORT_ES6=1`로 만든 `engine.mjs`는 그 방식으로 불러올 수 없다.)

| 방향 | 메시지 | 처리 |
|---|---|---|
| 화면 → 워커 | `{ type: 'init' }` | 9–11줄: 처음 한 번만 `Module()`을 불러 Promise를 `modPromise`에 보관. 12–13줄: 적재가 끝나면 `{ type: 'ready' }` |
| 화면 → 워커 | `{ type: 'optimize', payload: parsed }` | 16줄: `await modPromise`(적재 중이면 끝날 때까지 기다림) → 17줄 `callEngine` |
| 워커 → 화면 | `{ type: 'success', numPlans, plans }` | 18줄. `plans`는 이미 해석된 객체 배열(rev 1은 날 출력 배열을 보냈다) |
| 워커 → 화면 | `{ type: 'error', error: 문자열 }` | 19–20줄: `callEngine`의 예외(엔진 오류 포함)를 문자열로 |

- `payload`는 `parseData`의 반환 객체이고, 그 안의 `Float64Array`·`Int32Array`는 `postMessage`의 구조적 복제로 **복사**되어 간다
  (transfer 목록을 쓰지 않으므로 화면 쪽 배열도 그대로 남는다).
- 메시지에 요청 번호가 없다. 화면이 한 번에 하나만 보낸다는 가정이다(3.6절 `pending*`).
- `init` 처리의 `await modPromise`는 try 밖이다. `Module()`이 실패하면(예: `engine.wasm`을 못 받음) `ready`가 오지 않고, 다음 `optimize`의
  16줄 `await`가 같은 거부를 다시 받아 `error` 메시지로 간다. 반대로 **워커 파일 자체를 불러오지 못하면**(예: `engine.mjs` 404) onmessage가
  없으므로 화면은 아무 답도 받지 못한다 — 아래 3.6절에서 실제로 확인한 동작.

### 3.7 커밋 해시 자리 (index.html 50줄 + engine.yml 87줄)

저장소의 index.html에는 `<span id="commitHash">UNKNOWN_COMMIT</span>`이 그대로 있다. CI의 `Assemble Static Site` 단계가 `site/`에 복사한
사본에만 `sed -i "s/UNKNOWN_COMMIT/${GITHUB_SHA}/" site/index.html`을 적용한다. `GITHUB_SHA`는 Actions가 주는 실행 커밋의 40자 해시다.
- 이 세션에서 같은 `sed`를 `GITHUB_SHA=79099ec985a304090f88db3f1d5200a0e8c36ecb`로 사본에 돌린 결과 50줄이
  `Build commit hash: <span id="commitHash">79099ec985a304090f88db3f1d5200a0e8c36ecb</span>`가 되었다. `UNKNOWN_COMMIT`은 파일에 한 번만 있다.
- 작업 트리의 원본은 바뀌지 않으므로, 로컬에서 그냥 열면 `UNKNOWN_COMMIT`이 보이는 것이 정상이다.
- 지금 smoke 시험은 해시를 검사하지 않는다(SPEC 6.2 deploy 줄 "화면에 커밋 해시 표시"는 VM-19 몫).

### 3.10 `tests/smoke.mjs`와 http-server — 브라우저가 실제로 페이지를 연다

흐름: Chromium headless 실행 → 콘솔 `error`와 `pageerror`를 `hasError`로 모음(8–18줄) → `SITE_URL`(CI는 `http://localhost:8080/`)로 이동
→ `#btnExample` 클릭 → `#btnOptimize` 클릭 → `text=Found 5 plans`가 10초 안에 나타날 때까지 대기(32줄) → 오류가 있었으면 exit 1
→ 스크린샷 `smoke-screenshot.png` → `SMOKE TEST PASSED`.
- 32줄의 대기가 시간 초과하면 예외가 나고, 이 async 함수에는 `catch`가 없어서 처리되지 않은 거부로 Node가 종료 코드 1로 끝난다(단계 실패).
- 검사하는 것은 "Found 5 plans" 글자와 콘솔 오류 없음뿐이다. 계획 내용·총액은 보지 않는다. SPEC V7의 "공유 링크를 새 창에서 열어 같은 총액"은
  공유 링크(F6)가 아직 없어 빠져 있다.
- 21–22줄 주석과 기본값은 `file://…/site/index.html`이지만, CI는 `SITE_URL`을 주어 http로 연다. 이유는 다음 실험 그대로다.

**왜 `file://`이 아니라 http-server인가.** 같은 index.html·model.mjs·worker.mjs를 스크래치 폴더에 두고 Playwright(이 세션의 1.56.1)로
열어 본 결과:

`file://` 페이지의 출처는 `null`이고, Chromium은 모듈 스크립트를 CORS 규칙으로 가져오는데 `file:` 체계는 그 대상이 아니다. 그래서
**첫 모듈 import(model.mjs)부터 막혀** 스크립트 전체가 실행되지 않는다 — 예시 버튼을 눌러도 이동 칸이 빈 그대로(1줄)다. 모듈 워커
(`new Worker(..., { type: 'module' })`)와 그 안의 `import './engine.mjs'`도 같은 방식으로 가져오므로 같은 이유로 `file://`에서는 쓸 수 없다
(위 실험에서는 첫 import에서 이미 멈춰 워커까지 가지 않았다). http로 열면 모듈이 적재되어 예시 칸이 449줄(448줄 + 끝 빈 줄)로 채워지고,
이 실험 사이트에는 `engine.mjs`를 넣지 않았으므로 워커의 import만 실패한다.

모듈 워커만 따로 확인하려고, 일반 `<script>`에서 `new Worker("w.mjs", { type: "module" })`만 하는 페이지(`w.mjs`는 `self.postMessage("hello")`
한 줄)를 두 방식으로 열었다:

```text
--- file:// module worker
[pageerror] Failed to construct 'Worker': Script at 'file:///tmp/claude-0/vm18/exp/wk/w.mjs' cannot be accessed from origin 'null'.
--- http module worker
[console.log] worker said hello
```

결론: 모듈 스크립트와 모듈 워커를 쓰는 페이지는 http(s)로 제공해야 한다. http-server로 열면 실제 배포(GitHub Pages, https)와 같은 조건이 된다.

```diff
+        const errStr = mod.UTF8ToString(errPtr);
+        mod._free(ptrPrice); mod._free(ptrMinutes); mod._free(ptrLodging); mod._free(ptrStayMin); mod._free(ptrStayMax); mod._free(ptrOut);
+        throw new Error(errStr);
+    }
+    
+    const outActual = new Float64Array(mod.HEAPF64.subarray(ptrOut / 8, ptrOut / 8 + out_len));
+    const plans = decodePlans(outActual, numPlans, p.k, p.V, p.nodeToCity, p.modeIdxToName, p.startDate);
+    
+    mod._free(ptrPrice); mod._free(ptrMinutes); mod._free(ptrLodging); mod._free(ptrStayMin); mod._free(ptrStayMax); mod._free(ptrOut);
+    
+    return plans;
+}
```

**교훈: 시험은 화면이 쓰는 것과 같은 코드 경로를 지나가야 한다.**
1. **같은 일을 하는 코드가 두 벌이면, 시험은 한 벌만 지키고 화면은 다른 벌을 쓴다.** 공유 함수(`callEngine`, `getExampleData`)를 만들고,

5. **같은 경로의 끝은 브라우저다.** Node 시험은 화면의 DOM, 모듈 적재, 워커, `postMessage`를 지나지 않는다. 그 구간은 smoke가 맡는다.

   드러난다(연습 문제 2).

### 6.2 연습 문제

1. **줄 번호 시험 강화.** `model.test.mjs`에 이동 CSV가 `"\n\nSeoul,Busan,2027-04-01,Bus,10,10"`인 경우를 추가해 `line 3`을 기대한다.
   그다음 model.mjs 19줄의 `.filter`를 `.map` **앞**으로 옮겨 일부러 깨 보고, 새 시험만 실패하는지(기존 `line 1` 시험은 통과하는지) 본다.
   같은 방식으로 방문 도시 형식 오류(`"B,1,2\n\nC,1"` → `line 3`)도 시험으로 만든다.
2. **오류 경로를 실제로 지나게 하기.** (가) `engine/CMakeLists.txt` 18줄 링크 옵션에 `"-sEXPORTED_RUNTIME_METHODS=UTF8ToString"`을 더한다.
   (나) `callEngine`의 해제를 `try { … } finally { 6개 free }` 하나로 바꿔, 어떤 예외에서도 해제되게 한다(5장의 가짜 모듈로 `still allocated 0` 확인).
   (다) `wasm.test.mjs`에 방문 도시가 빈 입력을 넣어 `assert.throws(…, /visits must be 1..10/)`를 추가한다. (가) 없이 (다)만 먼저 push해서
   3.4절의 판단(`mod.UTF8ToString is not a function`)이 맞는지 CI 로그로 확인하고, 그다음 (가)를 더해 녹색이 되는지 본다.
3. **워커 시간 제한.** 화면 122–126줄의 Promise에 `setTimeout`(예: 30초)을 걸어 시간이 지나면 `reject(new Error('timeout'))`. 워커 생성 직후
   `worker.onerror`도 달아 대기 중인 요청을 실패시킨다. 확인: `engine.mjs` 없이 http로 열면 3.6절의 "Optimizing..." 대신 오류가 보여야 한다.
4. **가능한 여행이 없을 때.** 지금 화면은 n = 0이면 `Found 0 plans. No valid plans found.`를 보인다(130–133줄). SPEC 4.1의 말 그대로
   "가능한 여행 없음(no feasible trip)"으로 문구를 정하고, smoke 시험에 n = 0 시나리오를 추가한다: 예시를 불러온 뒤 계획 일수를 3으로 줄이면
   최소 6박이 들어가지 않으므로 엔진이 0을 돌려줄 것으로 **예상**한다(입력 검사 `validate`는 통과하는 입력이다. 실제 값은 CI에서 확인).
   기대 문구가 보이고 `.plan`이 0개인지 확인한다.
5. **기간 밖 줄 수를 화면에.** 115–117줄의 `console.warn`을 상태 줄에도 보이게 바꾸고(SPEC 4.3 "몇 줄인지 알린다"), 숙박 CSV가 비었으면
   "숙박비 미포함"을 보인다. `parseData`가 숙박 줄 수를 돌려주도록 하고 model 시험을 먼저 쓴다.
6. **인덱스 배치를 일부러 깨기.** model.mjs 106줄을 `((t.to * N + t.from) * days + t.day) * M + t.mode`(a, b 뒤바꿈)로 바꾸고 무엇이 잡는지 본다.
   (가) model 시험 3번(55–57줄)이 잡는다. 이 문서를 쓰며 사본에서 해 본 결과 `not ok 3`, `expected: 100`, `actual: -1`(# pass 2, # fail 1). (나) 그런데 55줄 공식도 같이 바꾸면? model 시험은 통과한다 — 공식을 공식으로
   검사하기 때문(3.8절). (다) 그 상태로 CI에 올리면 wasm.test의 89–102줄(CSV 대조)이나 56–57줄(출발·귀국)이 잡는지, 아니면 계획 0개로
