**한 번의 `bms_step()` 흐름 (`ab25915`).**
1. 측정 읽기: 채널마다 신호 범위 검사(SWR-002/003) → 평균 갱신(보고용, 아무도 읽지 않음 — 2.2절).
2. 신호 고장 디바운스(SWR-004).
3. 보호 조건 5개를 **이번 샘플 값**으로 계산 → 조건마다 디바운스 → 3회 연속이면 고장 비트(SWR-005~009).
4. 고장 비트가 있으면 FAULT, 없으면 `switch`로 상태 전이(SWR-012~014).
5. 출력: `contactor_close = (state == CLOSED)` — 고장이 생긴 **그 스텝**에 컨택터가 열린다(SWR-010, 011).

**왜 rev 1이 불합격이었나.** rev 1(`97de96b`)은 3단계의 보호 조건을 원시 샘플이 아니라 1단계의 **이동 평균**으로 계산했다. SPEC C2-2가 "이동 평균"을
측정 처리에 넣으라고 했기 때문에 VM은 평균을 만들고, 그 평균을 보호 판정에 연결했다. 그런데 SWR-005~009의 문장은 "전압이 4.25 V를 초과하는 **상태가
3회 연속 샘플** 지속되면"이다. 판정 대상은 샘플이고, 잡음 거르기는 이미 "3회 연속"(디바운스)이 맡고 있다. 평균을 앞에 두면:

- 정상 3700 mV에서 셀 하나가 4251 mV가 되어도 OV가 **영영** 걸리지 않는다(평균이 4250에서 멈춤, 2.5절의 산수).
- 3700 → 2799 mV 저전압은 3번째가 아니라 **12번째** 샘플에서 걸린다(120 ms — SWR-010의 100 ms도 넘는다).
- 그런데도 rev 1의 시험은 15/15 녹색이었다. 모든 보호 시험이 `setUp()` 직후 **첫 샘플부터 경계값**을 넣었고, 첫 샘플은 평균을 그 값으로 시드하므로
  평균 = 원시값인 경로만 시험했다.

rev 2(`ab25915`)는 판정을 원시 샘플로 옮기고(바뀐 줄 4개), 보호 시험을 "정상값 10회 → 경계값"으로 바꿨다(2.3절). 이 세션에서 rev 2 시험을
rev 1 코드에 돌리면 보호 시험 4개가 실패한다(2.6절) — 새 시험은 옛 결함을 잡는다.

**`bms.h`.**
- `bms_inputs_t.contactor_req` (40줄): VCU_Cmd.ContactorReq를 펌웨어 쪽에서 본 값. CAN 수신(4주차)은 아직 없으므로 시험이 이 칸을 직접 쓴다.
  `current_ma`는 39줄 주석대로 **양수 = 방전**, 그래서 "충전 중"은 `current_ma < 0`이다(SWR-008, 009).
- `bms_t`에 더한 것: 평균 배열 두 개(54–55), 첫 스텝 표시 `first_step`(56), 보호 조건마다 디바운스 카운터 하나씩(57–61). 모두 고정 크기 —
  동적 메모리 없음(SPEC C2 완료 기준).
- 카운터를 조건마다 따로 두는 이유: "OV 2번 + UV 1번"이 "보호 조건 3번"으로 합쳐 세어지면 안 된다. 각 SWR이 **자기 조건**의 3회 연속을 요구한다.
- 반대로 셀 4개는 카운터 하나(`ov_count`)를 같이 쓴다. "어느 셀이든"이므로 샘플마다 셀 0이 넘고, 다음 샘플엔 셀 1이 넘어도 연속으로 센다.
  SWR 문장("어느 셀이든 … 상태가 3회 연속")을 그대로 읽은 것이다.

**`bms_config.h`.**
- 문턱값 6개는 SWR 숫자 그대로: 4.25 V → 4250 mV, 2.80 V → 2800 mV, 60.0 °C → 600 (0.1 °C 단위), 0.0 °C → 0, 150 A → 150000 mA, 50 A → 50000 mA.

### 2.2 `bms.c` 전체 (`ab25915`, 132줄)

```c
#include "bms.h"

#include <string.h>

static bool cell_signal_ok(uint16_t mv)
{
    return mv >= BMS_CELL_SIGNAL_MIN_MV && mv <= BMS_CELL_SIGNAL_MAX_MV;
}

static bool temp_signal_ok(int16_t ddegc)
{
    return ddegc >= BMS_TEMP_SIGNAL_MIN_DC && ddegc <= BMS_TEMP_SIGNAL_MAX_DC;
}

/* Count consecutive bad samples; return true once the debounce limit is reached. */
static bool debounce(uint8_t *count, bool bad)
{
    if (!bad) {
        *count = 0u;
        return false;
    }
    if (*count < BMS_FAULT_DEBOUNCE_SAMPLES) {
        (*count)++;
    }
    return *count >= BMS_FAULT_DEBOUNCE_SAMPLES;
}

void bms_init(bms_t *bms)
{
    (void)memset(bms, 0, sizeof(*bms));
    bms->state = BMS_STATE_INIT;
    bms->first_step = true;
}

void bms_step(bms_t *bms, const bms_inputs_t *in, bms_outputs_t *out)
{
    bool cells_ok = true;
    bool temps_ok = true;

    for (int i = 0; i < BMS_NUM_CELLS; i++) {
        bool ok = cell_signal_ok(in->cell_mv[i]);
        cells_ok = cells_ok && ok;   /* SWR-002 */
        if (bms->first_step) {
            bms->cell_mv_avg[i] = in->cell_mv[i];
        } else if (ok) {
            bms->cell_mv_avg[i] = (uint16_t)((bms->cell_mv_avg[i] + in->cell_mv[i]) / 2);
        }
    }
    for (int i = 0; i < BMS_NUM_TEMPS; i++) {
        bool ok = temp_signal_ok(in->temp_ddegc[i]);
        temps_ok = temps_ok && ok; /* SWR-003 */
        if (bms->first_step) {
            bms->temp_ddegc_avg[i] = in->temp_ddegc[i];
        } else if (ok) {
            bms->temp_ddegc_avg[i] = (int16_t)((bms->temp_ddegc_avg[i] + in->temp_ddegc[i]) / 2);
        }
    }
    bms->first_step = false;

    if (debounce(&bms->sig_cell_count, !cells_ok)) {
        bms->faults |= BMS_FAULT_SIG_CELL;
    }
    if (debounce(&bms->sig_temp_count, !temps_ok)) {
        bms->faults |= BMS_FAULT_SIG_TEMP;
    }

    /* Protection checks */
    bool any_ov = false;
    bool any_uv = false;
    bool any_ot = false;
    bool any_utc = false;
    bool oc = false;

    for (int i = 0; i < BMS_NUM_CELLS; i++) {
        if (in->cell_mv[i] > BMS_OV_THRESHOLD_MV) {
            any_ov = true;
        }
        if (in->cell_mv[i] < BMS_UV_THRESHOLD_MV) {
            any_uv = true;
        }
    }

    for (int i = 0; i < BMS_NUM_TEMPS; i++) {
        if (in->temp_ddegc[i] > BMS_OT_THRESHOLD_DC) {
            any_ot = true;
        }
        if (in->current_ma < 0 && in->temp_ddegc[i] < BMS_UTC_THRESHOLD_DC) {
            any_utc = true;
        }
    }

    if (in->current_ma > BMS_OC_DISCHARGE_MA || in->current_ma < -BMS_OC_CHARGE_MA) {
        oc = true;
    }

    if (debounce(&bms->ov_count, any_ov)) { bms->faults |= BMS_FAULT_OV; }
    if (debounce(&bms->uv_count, any_uv)) { bms->faults |= BMS_FAULT_UV; }
    if (debounce(&bms->ot_count, any_ot)) { bms->faults |= BMS_FAULT_OT; }
    if (debounce(&bms->utc_count, any_utc)) { bms->faults |= BMS_FAULT_UTC; }
    if (debounce(&bms->oc_count, oc)) { bms->faults |= BMS_FAULT_OC; }

    /* State machine */
    if (bms->faults != 0u) {
        bms->state = BMS_STATE_FAULT; /* SWR-004 to SWR-009 */
    } else {
        switch (bms->state) {
            case BMS_STATE_INIT:
                if (cells_ok && temps_ok) {
                    bms->state = BMS_STATE_STANDBY; /* SWR-012 */
                }
                break;
            case BMS_STATE_STANDBY:
                if (in->contactor_req) {
                    bms->state = BMS_STATE_CLOSED; /* SWR-013 */
                }
                break;
            case BMS_STATE_CLOSED:
                if (!in->contactor_req) {
                    bms->state = BMS_STATE_STANDBY; /* SWR-014 */
                }
                break;
            case BMS_STATE_FAULT:
                /* Latched until diagnostics clear it */
                break;
        }
    }

    out->state = bms->state;
    out->faults = bms->faults;
    /* SWR-011: FAULT ignores ContactorReq */
    out->contactor_close = (bms->state == BMS_STATE_CLOSED);
}
```

**`debounce()` (16–26줄).** 카운터 하나와 "이번 샘플이 나쁜가"를 받는다.
- 좋은 샘플이면 카운터를 0으로 되돌리고 `false`. "연속"의 뜻이 이 한 줄이다.
- 나쁜 샘플이면 카운터를 하나 올리되 3(`BMS_FAULT_DEBOUNCE_SAMPLES`)에서 멈춘다(포화). `uint8_t`가 255를 넘어 0으로 돌아가는 일을 막는다.
- 카운터가 3 이상이면 `true`. 그래서 나쁜 샘플 1, 2번째는 `false`, **3번째 스텝에서 처음 `true`**.
- 샘플 순서로 쓰면: 나쁨(1, false) → 나쁨(2, false) → 좋음(0, false) → 나쁨(1) → 나쁨(2) → 나쁨(3, **true**).
- 시간으로는: 첫 나쁜 샘플이 들어온 스텝을 0 ms라 하면 고장은 20 ms 뒤 스텝(3번째 샘플)에 선다. SWR 문장의 "3회 연속 샘플(30 ms)"은 샘플 3개가
  덮는 시간이다. 어느 쪽으로 세어도 SWR-010의 100 ms 안이다.

**상태 기계 `switch` (106–125줄).**
- `INIT`: 셀·온도 모두 신호 범위 안이면 STANDBY(SWR-012). 첫 스텝(10 ms)에 바로 넘어간다. 채널이 계속 이상하면 디바운스로 FAULT에 간다.
- `STANDBY`: `contactor_req`가 1이면 CLOSED(SWR-013). 요청이 들어온 **같은 스텝**에 바뀌므로 10 ms ≤ 20 ms.
- `CLOSED`: `contactor_req`가 0이면 STANDBY(SWR-014). 마찬가지로 같은 스텝.
- `FAULT`: 아무것도 하지 않는다. 103줄 때문에 고장 비트가 있는 한 여기 오지도 않지만, 비트를 지우는 진단(4주차 이후 UDS 0x14)이 생기면 이 `case`가
  "그 뒤 어디로 가나"를 정할 자리다.
- `default`가 없다. 열거형의 네 값을 모두 `case`로 다뤘으므로 `-Wall`에 들어 있는 `-Wswitch`가, 나중에 상태를 하나 더하고 `case`를 빠뜨리면 경고
  (→ `-Werror`로 빌드 실패)를 낸다. `default:`를 넣으면 이 검사가 꺼진다.
- `bms_step`에는 `static` 지역 변수도 전역 변수도 없다. 모든 상태가 `bms_t`에 있으므로 같은 `bms_t`와 같은 입력이면 같은 출력(SPEC C2 완료 기준의 결정성).

**rev 2에도 남은 것: 아무도 읽지 않는 평균.** 40–58줄은 rev 2에서도 매 스텝 평균을 계산하지만, 보호 판정도 출력(`bms_outputs_t`)도 그 값을 쓰지 않는다.
rev 2 지시는 "필터 값은 **보고용으로만** 둘 수 있다"였는데, 보고하는 곳(CAN `BMS_CellV`, 4주차)이 아직 없다. 지금은 시험도 커버리지도 늘리지 않는
죽은 상태다(연습문제 7).

```c
  int s; for(s=1;s<=1000;s++){ bms_step(&b,&in,&out); if(out.faults & BMS_FAULT_OV) break; }
  printf("OV after normal: %s (steps=%d, avg=%u)\n", (out.faults&BMS_FAULT_OV)?"tripped":"NEVER", s, b.cell_mv_avg[0]);
  bms_init(&b); for(int i=0;i<4;i++) in.cell_mv[i]=3700;
  for(int k=0;k<10;k++) bms_step(&b,&in,&out);
  in.cell_mv[0]=2799;
  for(s=1;s<=1000;s++){ bms_step(&b,&in,&out); if(out.faults & BMS_FAULT_UV) break; }
  printf("UV after normal: steps=%d (SWR-006 wants 3)\n", s);
  return 0; }
```

모든 셀 3700 mV·온도 25.0 °C로 10번(정상 운전점) → 셀 0만 4251 mV로 올려 OV가 설 때까지 최대 1000번, 같은 방법으로 2799 mV에서 UV.
`gcc -std=c11 -I<fw>/include t.c <fw>/src/bms.c`로 각 커밋의 펌웨어와 묶었다(`git show <rev>:경로`로 스크래치 폴더에 꺼냄. 4장).

읽는 법: `steps=1001`은 루프가 1000번을 다 돌고 빠져나왔다는 뜻(OV 없음). rev 2에서는 둘 다 정확히 3번째 샘플. rev 2의 `avg=4182`는 보고용 평균이
아직 따라 올라가는 중이라는 것뿐, 판정과는 상관없다.

**산수: 왜 4250에서 멈추나.** rev 1의 갱신식은 `avg ← ⌊(avg + 4251) / 2⌋`(양수 정수 나눗셈 = 내림). 3700에서 출발하면:

```text
step  1  avg=3975
step  2  avg=4113
step  3  avg=4182
step  4  avg=4216
step  5  avg=4233
step  6  avg=4242
step  7  avg=4246
step  8  avg=4248
step  9  avg=4249
step 10  avg=4250
step 11  avg=4250
step 12  avg=4250
```

- 주장: `avg ≤ 4250`이면 다음 값도 `≤ 4250`이다. 증명: `avg + 4251 ≤ 8501`이고 `⌊8501 / 2⌋ = 4250`. 처음 값 3700 ≤ 4250이므로 귀납적으로 영원히
  `≤ 4250`, 즉 `> 4250`(OV 조건)은 한 번도 참이 되지 않는다.
- 일반화: 입력이 `v`로 고정되면 아래에서 올라오는 평균은 `v − 1`에서 멈춘다(`⌊(v − 1 + v) / 2⌋ = v − 1`). 문턱 `T`를 "초과"해야 하는 조건에서
  `v = T + 1`은 평균이 `T`에 멈춰 영원히 못 넘는다. `v = T + 2` 이상이어야 언젠가 넘는다(연습문제 1).
- 반대로 위에서 내려오는 평균은 `v`에 정확히 닿는다(`⌊(v + 1 + v) / 2⌋ = v`). 그래서 UV는 "걸리긴 하지만 늦게" 걸렸다:

```text
step  1  avg=3249  uv_count=0
step  2  avg=3024  uv_count=0
step  3  avg=2911  uv_count=0
step  4  avg=2855  uv_count=0
step  5  avg=2827  uv_count=0
step  6  avg=2813  uv_count=0
step  7  avg=2806  uv_count=0
step  8  avg=2802  uv_count=0
step  9  avg=2800  uv_count=0
step 10  avg=2799  uv_count=1
step 11  avg=2799  uv_count=2
step 12  avg=2799  uv_count=3  -> UV
```

  평균은 10번째 스텝에야 2800 아래가 되고, 거기서 디바운스 3회 → 12번째. 120 ms는 SWR-006의 30 ms의 4배, SWR-010의 100 ms보다도 길다.

0부터 4250까지 모든 정수 `x`에 대해 다음 평균의 최댓값과, 4251이 고정점이 아님을 기계로 확인:

```text
max over x<=4250 of (x+4251)//2 = 4250
fixed point from below: (4250+4251)//2 = 4250
```

**온도도 같은 함정이다.** top의 프로그램은 셀 전압만 봤다. 이 세션에서 같은 모양으로 온도를 보는 프로그램을 따로 써서(`scratchpad/bms24/t_temp.c`,
이 문서용으로 새로 쓴 것) 돌렸다:

```c
/* VM-24 study: OT (SWR-007) and charge-UT (SWR-008) one unit past the limit, from 25.0 degC. */
#include <stdio.h>
#include <string.h>
#include "bms.h"
static int run(int16_t t, int32_t ma, uint8_t bit, bms_t *b)
{
  bms_inputs_t in; bms_outputs_t out;
  bms_init(b); memset(&in, 0, sizeof in);
  for (int i = 0; i < 4; i++) in.cell_mv[i] = 3700;
  for (int i = 0; i < 2; i++) in.temp_ddegc[i] = 250;
  for (int k = 0; k < 10; k++) bms_step(b, &in, &out);
  in.temp_ddegc[0] = t; in.current_ma = ma;
  for (int s = 1; s <= 1000; s++) { bms_step(b, &in, &out); if (out.faults & bit) return s; }
  return 0;
}
int main(void)
{
  bms_t b; int s;
  s = run(601, 0, BMS_FAULT_OT, &b);
  printf("OT  601 dC: %s (avg=%d)\n", s ? "tripped" : "NEVER", b.temp_ddegc_avg[0]);
  if (s) printf("    at sample %d\n", s);
  s = run(-1, -1000, BMS_FAULT_UTC, &b);
  printf("UTC  -1 dC charging: %s (avg=%d)\n", s ? "tripped" : "NEVER", b.temp_ddegc_avg[0]);
  if (s) printf("    at sample %d\n", s);
  return 0;
}
```

- UTC −1은 **위에서 내려오는데도** 멈춘다. 평균이 0일 때 `(0 + (−1)) / 2`는 C에서 −0.5를 0 쪽으로 버려 **0**이다. 위의 "위에서 내려오면 닿는다"는
  양수(내림 = 버림)에서만 맞다. 음수에서는 버림이 올림이 되어 0 바로 아래에 닿지 못한다. 그래서 rev 1에서는 OV·OT·UTC 세 보호가 문턱 + 1단위에서
  영영 걸리지 않았고, UV는 4배 늦었다. 정상인 것은 원시값을 쓰던 OC뿐이었다.

### 2.6 왜 보호 문턱 앞에 필터를 두면 안 되나, 그리고 "정상 운전점에서 출발"하는 시험

**필터를 문턱 앞에 두면 생기는 일.**
1. **지연.** `avg ← (avg + new) / 2`는 1차 저역 통과 필터다. 계단 입력에 대해 매 스텝 남은 거리의 절반만 따라간다. 문턱과 정상값의 거리가 멀수록
   늦고(3700 → 2799는 10 스텝), 그 뒤에 디바운스 3회가 **또** 붙는다. 보호의 시간 예산(SWR-010 100 ms)을 필터가 먹는다.
2. **감쇠와 정수 오차.** 문턱 바로 바깥 값은 평균이 문턱에 "닿기만" 하고 넘지 못할 수 있다(2.5절). 보호는 정확히 경계에서 동작해야 하는데,
   필터가 경계를 옮긴다.
3. **이중 잡음 처리.** 잡음 한두 샘플로 고장이 서지 않게 하는 일은 이미 디바운스("3회 연속")가 한다. 요구사항이 정한 잡음 처리 방법이 그것이다.
   필터를 더 얹으면 요구사항이 정하지 않은 동작이 생긴다.
4. **요구사항 문장과 다름.** SWR-005~009는 "샘플"의 상태를 말한다. 필터된 값으로 판정하려면 요구사항(그리고 그 시간 예산)을 먼저 바꿔야 한다.

필터가 필요한 곳은 사람에게 보이는 값(SOC 표시, CAN의 셀 전압 보고)이고, 보호 경로는 원시 샘플 → 문턱 → 디바운스 → 컨택터로 짧게 둔다.
SPEC C2-2의 "이동 평균"은 측정 처리 기능이지 "보호를 평균으로 하라"는 뜻이 아니다 — 스펙의 두 줄(2: 측정 처리, 3: 보호)을 그대로 이어 붙인 것이
rev 1의 설계 실수다.

**시험 설계: 정상 운전점에서 출발하라.** 필터·디바운스·적분처럼 **상태가 있는** 코드는 같은 입력이라도 그 전에 무엇이 들어왔는지에 따라 결과가 다르다.
rev 1 시험의 `setUp()` → 바로 경계값은 "평균 = 경계값"인 특수한 시작점만 시험했다. 실제 차량에서 4251 mV는 항상 정상값에서 **넘어온다**.

```bash
#   bms24.sh repro <rev> [prog.c]   compile prog.c (default bmscheck/t.c) with <rev>'s bms.c and run it
#   bms24.sh unity <bms_rev> <test_rev>   run <test_rev>'s Unity tests against <bms_rev>'s bms.c

extract() { # <rev> -> prints dir

  done
  echo "$d"

    "$d/repro" ;;

    (cd "$t" && "$out/t") | sed "s#^$t/##" || true ;;
esac
```

<summary>1–2</summary>

1. 걸린다. 위에서 본 일반화대로 `v = T + 2 = 4252`는 평균이 4251까지 올라가 문턱 4250을 넘는다. 다만 늦다. rev 1의 갱신식과 디바운스를 그대로 흉내 내면:

```text
step  1  avg=3976  ov_count=0
step  2  avg=4114  ov_count=0
step  3  avg=4183  ov_count=0
step  4  avg=4217  ov_count=0
step  5  avg=4234  ov_count=0
step  6  avg=4243  ov_count=0
step  7  avg=4247  ov_count=0
step  8  avg=4249  ov_count=0
step  9  avg=4250  ov_count=0
step 10  avg=4251  ov_count=1
step 11  avg=4251  ov_count=2
step 12  avg=4251  ov_count=3  -> OV
```

   12번째 샘플(120 ms). 4251은 "영영", 4252는 "4배 늦게" — 문턱 + 1단위 차이로 동작이 뒤바뀐다는 것 자체가 필터를 문턱 앞에 두면 안 되는 이유다.
2. C의 정수 나눗셈은 0 쪽으로 버린다(C99부터 규정). 평균이 0이 되면 `(0 + (−1)) / 2 = −1 / 2 = 0`이라 −1에 닿지 못하고 0에 머문다. 0은 `< 0`이 아니므로
   UTC 조건이 거짓. UV는 양수끼리라 버림 = 내림이고, 위에서 내려오는 평균은 `⌊(v + 1 + v) / 2⌋ = v`로 정확히 2799에 닿는다(10번째 스텝).

3. 같은 파일 모양으로:
   `setUp(); step_n(10); in.cell_mv[0] = 4251; step_n(2); in.cell_mv[0] = 3700; step_n(1); in.cell_mv[0] = 4251; step_n(2);`
   `TEST_ASSERT_EQUAL(0, out.faults & BMS_FAULT_OV); step_n(1); TEST_ASSERT_NOT_EQUAL(0, out.faults & BMS_FAULT_OV);`
   태그는 `/* @verifies SWR-005 */`. 리셋 줄(`debounce` 18–21줄)을 지우면 이 시험이 실패하는지 확인한다(시험이 그 줄을 지키는지).
4. 넘기는 값을 5000 → **4251**(문턱 바로 바깥)로 바꾸고, 스텝마다 단언한다: 첫째·둘째 샘플 뒤 `CLOSED`·`contactor_close == true`, 셋째 샘플 뒤
   `FAULT`·`contactor_close == false`. 시간은 "열린 스텝 번호 × `BMS_TASK_PERIOD_MS` ≤ 100"으로 계산해 `TEST_ASSERT_LESS_OR_EQUAL(100, …)`로
   SWR-012 시험(47줄)과 같은 모양으로 드러낸다. 이렇게 바꾼 시험은 rev 1에서 실패한다(2.4절의 `317e768`이 바로 이 시험이었다).
5. 전이를 먼저 하면 같은 스텝에서 STANDBY → CLOSED가 일어난 뒤 FAULT로 덮인다. 출력은 상태에서만 나오므로 결과는 같아 보이지만, 전이 코드가
   부수 효과(예: 4주차의 CAN 메시지, 컨택터 명령을 따로 내는 코드)를 갖게 되면 고장 스텝에 "닫힘" 명령이 한 번 나갈 수 있다 — SWR-011(FAULT에서 닫지 않음)과
   SWR-013의 "활성 고장이 없으면"을 어긴다. SWR-010은 같은 스텝에서 FAULT가 되므로 시간은 그대로다. 고장 우선이 맞는 순서다.

6. 이 헤더는 `bms.h`(가드 있음)에서만 인클루드되므로 실제로 두 번 읽히지 않고, 두 번 읽혀도 **똑같은 글자**의 매크로 재정의는 C에서 허용된다. 그래도
   (가) 누가 나중에 한 쪽 값만 바꾸면 재정의 오류나 경고가 나고, (나) "가드 안에 모든 내용"이라는 규칙을 깬 파일은 리뷰와 정적 분석(4주차 cppcheck,
   MISRA 계열 규칙)에서 지적된다. `#endif` 앞으로 옮긴다.
7. (가) 지운다: 평균 배열·`first_step`·40–58줄의 평균 부분을 없애고 `ok` 계산만 남긴다. 시험은 그대로 녹색이어야 한다(아무도 안 읽었으므로).
   (나) 쓴다: `bms_outputs_t`에 보고용 값으로 내보내고(4주차 `BMS_CellV`), 시험을 단다 — 계단 입력에서 평균이 기대값을 따라가는지, 신호 고장 샘플이
   평균에 안 들어가는지, 그리고 **평균이 바뀌어도 보호 결과는 원시값 기준**인지. 어느 쪽이든 "평균이 보호에 쓰이지 않는다"를 시험으로 고정한다.
8. SWR-005~009는 샘플의 상태와 "3회 연속"을 정한다. 잡음 처리는 그 디바운스가 맡고, 시간 예산은 SWR-010의 100 ms다. 평균을 넣으려면 (1) 요구사항을
   "필터된 값"으로 바꾸고, (2) 필터 지연 + 디바운스가 최악의 계단(정상값 → 문턱 + 1단위)에서도 100 ms 안인지 분석·시험하고, (3) 문턱 + 1단위가
   반드시 걸리는지(정수 반올림 포함) 보여야 한다. 그 전에는 보호 경로에 필터를 두지 않는다. 잡음이 실제로 문제라면 하드웨어 RC 필터나 AFE의 평균
   기능처럼 **샘플 이전**에서 다루고, 그 지연을 요구사항에 넣는다.
